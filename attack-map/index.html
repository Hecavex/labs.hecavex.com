Worked analytical exercise · synthetic data

A tracking request is not a compromise

Decision: do these observations justify checking one recipient's identity or mailbox telemetry? Start with the bounded APT31 source claim, not an actor verdict. The fictional records below illustrate why tracking reconnaissance and remote mailbox collection need different evidence.

Prerequisites: understand mail proxy behavior, identity-to-recipient mapping and UTC timestamps. Real follow-up requires authorised access to appropriate telemetry and a documented retention window. Do not submit production logs here. This page makes no candidate-domain or malware requests.

Fictional inputs are available in the downloadable fixture.

Complete static worked example — available without JavaScript

Input: an email-image request at 08:00 UTC is labelled security-proxy; no identity or mailbox events are supplied.

Transformation: count one image request and zero identity or mailbox events; zero recipient-confirmed identity/time joins. Proxy retrieval is a competing explanation.

Output: tracking-ambiguous. Ask whether a recipient actually opened the message; do not label an account compromised. Stop the recipient-specific chain when the initiator cannot be established.

Other controls: a confirmed recipient open followed by that identity's failed sign-in within one hour justifies a bounded follow-up, not a compromise finding. Approved-client mailbox reads have a benign alternative. Missing telemetry produces an explicit stop, never a successful defensive test.
